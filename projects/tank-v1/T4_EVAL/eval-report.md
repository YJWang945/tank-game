## 二、逐 Bug 评估

### B1 — Canvas ID 不匹配

| 维度 | 评估 |
|------|------|
| **真实性** | 确认。HTML `id="game-canvas"` ≠ JS `"gameCanvas"`，`getElementById` 返回 `null` |
| **严重度** | 阻断。游戏完全无法启动，页面空白无反应 |
| **根因** | 命名风格不一致（HTML kebab-case vs JS camelCase） |
| **是否必须修复** | **是。不修复则游戏不可用，后续所有测试无意义** |
| **建议修复方式** | 统一为 `game-canvas`（kebab-case，符合 HTML 规范）。改动 1 行（main.js:2） |
| **修复成本** | 极低，改 1 个字符串 |

### B2 — EnemyController.update 过早 return

| 维度 | 评估 |
|------|------|
| **真实性** | 确认。`return tank.shoot()` 在 for 循环内，直接退出整个方法 |
| **严重度** | 严重。敌人 AI 行为异常：后面敌人跳过更新、同一帧仅一个敌人可射击 |
| **根因** | 错误使用 `return` 代替收集-返回模式 |
| **是否必须修复** | **是。直接影响核心玩法的公平性和挑战性** |
| **建议修复方式** | `update()` 内部用 `bullets` 数组收集，循环结束后返回数组；`game.js` 调用方改为遍历 push |
| **修复成本** | 低，涉及 enemy.js 和 game.js 两处改动 |

### B3 — 隐形墙（墙壁碰撞矩形未更新）

| 维度 | 评估 |
|------|------|
| **真实性** | 确认。`getWallRects()` 仅在 `start()` 调用一次，砖墙被 `setTile()` 置空后 `this.walls` 仍保留旧矩形 |
| **严重度** | 中等。视觉上砖墙已消失，但子弹仍被不可见墙体阻挡。不影响游戏可启动性，但破坏体验一致性 |
| **根因** | 状态双写未同步：MAP_DATA（数据）与 walls 数组（碰撞）各自维护 |
| **是否必须修复** | **是。视觉反馈与实际行为不一致，属于可感知的功能缺陷** |
| **建议修复方式** | 方案 A：每帧在 `update()` 中调用 `getWallRects()` 刷新（简单但有冗余计算）；方案 B：`bullet.update()` 碰撞时同步从 `walls` 中移除对应矩形（更高效） |
| **修复成本** | 低，推荐方案 B |

### B4 — 双重回退

| 维度 | 评估 |
|------|------|
| **真实性** | 确认。墙碰撞 undo 后，敌人碰撞再 undo，玩家被推回两倍 speed 距离 |
| **严重度** | 轻微。触发条件苛刻（需同一帧内同时撞墙和撞敌），视觉表现为短暂弹跳 |
| **根因** | 两次碰撞检测各自独立 undo，缺少"已回退"标记 |
| **是否必须修复** | **建议修复，但可作为低优先级**。不影响游戏可玩性，偶发场景 |
| **建议修复方式** | 合并碰撞检测为单次判断：收集所有碰撞 → 若有任一碰撞则仅 undo 一次。或添加 `blocked` 标记 |
| **修复成本** | 极低，改 game.js 碰撞逻辑 |

## 三、迭代决策

### 结论：启动迭代修复

四项意见经评估均真实有效，无假阳性，无需争议。建议按以下优先级分批修复：

**第一批（阻断修复，预期 < 5 分钟）：**
- B1：统一 Canvas ID

**第二批（功能修复，预期 < 15 分钟）：**
- B2：重构 Enemy 射击循环
- B3：修复隐形墙碰撞

**第三批（打磨优化）：**
- B4：合并碰撞回退逻辑

### 回归验证计划

修复完成后，建议执行以下回归检查：

1. 浏览器打开 `index.html`，确认游戏能正常启动
2. 确认 5 个敌人均能独立移动和射击
3. 确认子弹击碎砖墙后，后续子弹能穿过该区域
4. 确认玩家不能穿墙、不能穿过敌人
5. 全流程通关验证（消灭全部敌人 → YOU WIN）
6. 死亡验证（HP 归零 → GAME OVER）
