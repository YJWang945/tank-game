## Bug 清单

### Bug #1 [阻断] Canvas ID 不匹配导致游戏无法启动

**文件**: `js/main.js:2` / `index.html:11`

**现象**: `main.js` 中使用 `getElementById('gameCanvas')` 查找 Canvas，但 HTML 中 Canvas 的 id 为 `game-canvas`。`getElementById` 返回 `null`，游戏初始化失败，页面无任何响应。

**代码对比**:
- HTML: `<canvas id="game-canvas" width="800" height="600"></canvas>`
- JS: `const canvas = document.getElementById('gameCanvas');`

**修复建议**: 将 JS 中的 `'gameCanvas'` 改为 `'game-canvas'`，或将 HTML 中的 `id="game-canvas"` 改为 `id="gameCanvas"`。推荐统一使用 `game-canvas`（HTML 风格）。

**严重程度**: 阻断 — 游戏完全不可用

---

### Bug #2 [严重] EnemyController.update 过早 return 导致敌人行为异常

**文件**: `js/enemy.js:87`

**现象**: 在 `update()` 方法的 for 循环中，当第一个存活敌人满足射击条件时，`return tank.shoot()` 直接退出整个方法。导致：
- 数组后面的敌人本帧完全不被处理（不移动、不转向、不射击）
- 同一帧永远只有一个敌人能发射子弹
- 索引越靠前的敌人"越活跃"，靠后的敌人几乎不动

**代码**:
```javascript
for (let i = 0; i < this.tanks.length; i++) {
    // ... movement, collision ...
    if (this.shootTimers[i] <= 0) {
        this.shootTimers[i] = ENEMY_SHOOT_INTERVAL + Math.floor(Math.random() * 80);
        return tank.shoot();  // ← BUG: 应收集子弹后继续循环
    }
}
return null;
```

**修复建议**: 改为收集机制 — 用 `bullets` 数组收集所有敌人产生的子弹，循环结束后返回数组。调用方（game.js）也需相应改为遍历数组 push。

**严重程度**: 严重 — 影响核心玩法体验（敌人行为不符合预期）

---

### Bug #3 [轻微] 玩家同时碰撞墙壁和敌人时可能双重回退

**文件**: `js/game.js:50-60`

**现象**: 玩家移动后先检测墙壁碰撞并 undo，再检测敌人碰撞并再次 undo。若玩家同时与墙壁和敌人碰撞，会被回退两次（超出原始位置）。

**修复建议**: 统一碰撞检测后再决定是否 undo，或在第一次 undo 后更新位置再检测后续碰撞。

**严重程度**: 轻微 — 偶发场景，视觉上表现为"弹跳"，不影响游戏可玩性
